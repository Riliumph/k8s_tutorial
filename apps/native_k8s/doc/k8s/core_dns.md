
起動時にCoreDNSのloopプラグインが`8401630501888128776.5452946643669077166.`（FQDN）にDNSクエリを送信する。これはDNSループを検知するための自己診断処理である。  

> FQDN（ホスト名）
>
> - `google.com.`
> - `8401630501888128776.5452946643669077166.`
> は同じ構造

そのクエリでループを検知して異常終了している。

```bash
CoreDNS
↓
127.0.0.11
↓
(省略)
↓
CoreDNS
```

となっており、ループしているようだ。

### 環境のリゾルバ

ローカルのresolve.confを見てみる。

```conf
# Generated by Docker Engine.
# This file can be edited; Docker Engine will not make further changes once it
# has been modified.

nameserver 127.0.0.11
search host.local
options ndots:0

# Based on host file: '/etc/resolv.conf' (internal resolver)
# ExtServers: [host(127.0.0.11)]
# Overrides: []
# Option ndots from: host
```

Dockerが自動で作っているので、ホストのものと全く同じ物ができている。  
特に`namespace 127.0.0.11`も特徴的でdocker環境においてコンテナが内部的に利用するDNSのアドレスとしてよく使われる。

> ループバックアドレス  
> 127.0.0.1 ～ 127.255.255.255までのアドレスで予約されている。

## ConfigMapを更新

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: coredns
  namespace: kube-system
data:
  Corefile: |
    .:53 {
        errors
        health {
           lameduck 5s
        }
        ready
        kubernetes cluster.local in-addr.arpa ip6.arpa {
           pods insecure
           fallthrough in-addr.arpa ip6.arpa
           ttl 30
        }
        prometheus :9153
        forward . 8.8.8.8 1.1.1.1 {
           max_concurrent 1000
        }
        cache 30
        loop
        reload
        loadbalance
    }
```

コマンドで以下の順に適用させる。（１回のコマンドで３つが書き換わる）

- ローカルの coredns.yaml
- Kubernetes API Server
- ConfigMap coredns

```console
# kubectl apply -f /etc/kubernetes/config_map/coredns.yaml
```
