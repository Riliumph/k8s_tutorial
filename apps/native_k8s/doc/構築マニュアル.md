# 構築マニュアル

3台のdebianコンテナをメタルサーバーに見立ててクラスターを構築する手順。  
コンテナ特有の`systemd`の無効化などがあり、必要要素を一つずつ確認する。

## リソースの管理について

`kubelet`と`containerd`は両方が`cgroup`を用いてリソースを管理する。  

> cgroupについては[ここ](./kernel/cgroup.md)

今回はsystemdで制御を行う。

### systemdの有効化

その場合、`CMD["/bin/bash"]`だとPID=1がbashになってしまいsystemdが機能していない。

必要があれば、dockerfile内のaptでsystemdをインストールしよう。  
それから、dockerfileの末尾を`CMD["/sbin/init"]`に変更する。  
`ps aux`してみて、PID=1が`systemd`で`contaienrd`も起動していることを確認する。

```console
root@k8s-master:/# ps aux
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.1 101560 11768 ?        Ss   10:16   0:00 /sbin/init
root          28  0.0  0.2  32968 12828 ?        Ss   10:16   0:00 /lib/systemd/systemd-journald
root          49  0.4  0.6 1500476 39480 ?       Ssl  10:16   0:01 /usr/bin/containerd
root          60  0.0  0.0   2952  1956 pts/0    Ss+  10:16   0:00 /sbin/agetty -o -p -- \u --noclear --keep-baud - 115200,38400,9600 xterm
root          83  0.0  0.0 101564  4920 ?        Ss   10:16   0:00 (agetty)
root         203  0.0  0.0   4204  3472 pts/1    Ss   10:18   0:00 bash
root         427  0.0  0.0   8104  4336 pts/1    R+   10:23   0:00 ps aux
```

## containerdの設定

`containerd`の設定を確認する。

```console
root@k8s-master:/# grep -n 'SystemdCgroup' /etc/containerd/config.toml
125:            SystemdCgroup = false
```

これが有効になっていないと`containerd`はリソースチェックが行えず、分裂することが出来ない。

> sedで編集するのは有り得ないので設定ファイルをCOPYする。

この設定が有効になれば、`containerd`は`systemd`を介して`cgroup`を使うことが出来る。

## ノードネットワークの設定

### L3ルーティング機能の可否

####

Linux KernelがパケットをL3ルーティング転送できるかを確認する。  

> ルーター的なアプリケーションがパケットを受けて別のところへ転送するのはアプリケーションとして自由だ。  
> この設定が有効じゃないとアプリケーションの転送も拒否されるとかではない。  
> あくまで、Linux公式の転送機能が有効になっているかを確かめる。

```console
$ docker compose exec -it k8s-master bash
root@k8s-master:/# sysctl net.ipv4.ip_forward
net.ipv4.ip_forward = 1
```

この転送機能がk8sにおけるPod間転送やCNIなどを構成してくれる。

### L2ルーティング機能の可否

> `br_netfilter`については[ここ](./kernel/br_netfilter.md)

モジュールのロード状況を確認する。

```console
# lsmod | grep br_netfilter
Module                  Size  Used by
br_netfilter           28672  0
bridge                286720  1 br_netfilter
```

どうやらロードされているらしい。
今はWSL2->devcontainer->Dockerの流れで立ち上がっているため、コンテナのLinux Kernelは一番底であるWSL2のLinux Kernelを使っている。  

もし、コンテナ環境であればホストのKernelにロードされることに注意しながら以下を実行する。

```console
root@k8s-master:/# modprobe br_netfilter
```

このコマンドは、今の起動でのみ有効なモジュールロードであることにも注意したい。  
もし、専用環境を構築していて、電源再起動時に自動でモジュールがロードされるように設定を永続化したい場合は[ここ](./kernel/module-load.md)を参照すること。

次に、Kernel parameterを確認する。

`br_netfilter`がロードされていることが分かったが、正しい設定がされているかを以下のコマンドで調査する。  
このパラメータは`br_netfilter`が提供するsysctlである。

```console
root@k8s-master:/# sysctl net.bridge.bridge-nf-call-iptables
net.bridge.bridge-nf-call-iptables = 1
```
